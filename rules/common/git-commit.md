# Git Commit 메시지 작성 가이드

## 핵심 원칙

1. **기존 컨벤션 우선** - 커밋 전에 해당 레포의 히스토리를 분석하고 그대로 따른다
2. **한글 작성** - 제목 설명과 본문은 한글로 쓴다
3. **간결함** - 무엇을, 왜 바꿨는지만 쓴다

## 1. 컨벤션 분석 (커밋 전 필수)

```bash
git log --format='%s' -20
```

다음을 파악해 그대로 맞춘다.

- 형식: `type(scope): 설명`, `[scope] 설명` 등
- type 종류와 scope 단위(디렉토리·패키지·기능명)
- 구분자(`—`, `-` 등)와 본문 사용 여부
- 브랜치명에 Jira 키(`[A-Z]+-[0-9]+`)가 있고 히스토리에서 키를 붙여 왔다면 같은 위치에 붙인다

히스토리가 없거나 일관된 패턴이 없으면 기본 형식을 쓴다.

```
<type>(<scope>): <한글 설명>
```

type: `feat` `fix` `refactor` `perf` `docs` `test` `chore` `ci`

## 2. 한글 작성 규칙

- 설명·본문은 한글로 쓴다.
- type·scope·식별자·파일 경로·명령어·고유명사·기술 용어는 원문을 유지한다.
- 제목은 72자 이내로 쓰고, 명사형이나 "~ 추가/수정/제거"로 끝낸다. 마침표는 찍지 않는다.
- 본문은 제목만으로 "왜"가 드러나지 않을 때만 쓴다.

**예시:**
- `feat(hooks): no-comments — 에이전트의 소스 코드 주석 작성을 PreToolUse 훅으로 차단`
- `fix(orchestrate): 병렬 에이전트 대기 시 폴링 금지 — 자가 웨이크업 루프 차단`
- `perf(settings): vitest 워커 3개 캡 — 병렬 orchestrate 세션 CPU 포화 방지`

## 3. 하지 말아야 할 것

- 영어로 설명 작성 (레포 컨벤션이 영어여도 설명은 한글로 쓴다)
- `Co-Authored-By: Claude ...`, `Claude-Session:` 등 AI 트레일러 추가
- "코드 수정", "업데이트" 같은 의미 없는 설명
- 시크릿·내부 URL 등 민감 정보 포함
